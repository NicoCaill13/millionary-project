# Plan — produit logiciel en libre-service

Business lucratif construit sur une compétence d'ingénierie, sans mission et sans prospection. Budget de départ : 200 USD.

Le million n'est pas un revenu à atteindre. C'est la valeur d'une petite société : environ 250 clients à 100 EUR/mois font 300 kEUR de revenu annuel récurrent, soit une valorisation de l'ordre de 0,9 à 1,2 MEUR (3 à 4 fois le récurrent). Horizon réaliste : 3 à 5 ans. Résultat le plus probable : un complément de quelques milliers d'euros par mois, ou rien.

## Contraintes

- Pas de mission, pas de régie, pas de journée facturée.
- Pas de prospection : aucun premier contact envoyé par moi.
- Pas de publicité payante, pas de stock, pas de trading, pas d'affiliation.
- Le temps disponible est de quelques heures par semaine, à côté d'un poste de Head of Engineering.
- Aucun code, aucune donnée, aucun processus de l'employeur dans le produit.
- Le domaine du produit ne recoupe pas le marché de l'employeur si le contrat l'interdit.
- Le contrat de travail est lu avant toute publication. S'il interdit l'activité, le plan s'arrête.

## Compétence utilisée

Conception et mise en production d'API et d'outillage : NestJS, Bun, Prisma, authentification, infrastructure, migrations de données, génération de documents, envoi d'e-mails. Le produit est un outil que cette compétence permet de construire seul.

## Modèle

Un abonnement, 30 à 150 EUR/mois, sur un créneau étroit.

- Un acheteur qui paie déjà pour ce type d'outil.
- Un usage récurrent.
- L'outil se décrit en une phrase.
- L'achat se fait en ligne, sans appel.
- La distribution ne dépend pas d'un message direct.
- Le produit n'est pas un clone facile pour un acteur déjà installé.

## Budget

| Poste | Montant |
| --- | --- |
| Nom de domaine | 15 USD, une fois le créneau choisi |
| Hébergement | 0 à 10 USD / mois |
| Paiement (Stripe ou Lemon Squeezy) | 0 USD d'avance, commission sur les ventes |
| API de modèle de langage (recherche, rédaction) | 50 USD |
| Réserve | le reste, non dépensé sans un blocage précis |

## Phases

### Semaines 1 à 2 — Choisir

Lister une vingtaine de niches B2B où l'outil existant est cher, daté ou mal noté. Pour chacune, relever des signaux publics :

- volume de recherche sur le problème ;
- avis négatifs (Capterra, G2, boutiques d'applications) ;
- plaintes sur des forums ;
- prix déjà pratiqués.

Garder une seule idée. Écrire la phrase : pour qui, quel résultat, à quel prix.

### Semaines 3 à 8 — Plus petite version payante

Une fonction, un paiement, pas de tableau de bord. La page de vente et le bouton de précommande existent avant que l'outil soit fini. Un paiement compte. Une liste d'intéressés ne compte pas.

### Semaines 9 à 12 — Distribution passive

À publier, sans écrire à personne :

- des pages « alternative à X » ;
- un petit outil gratuit qui mène au produit payant ;
- des réponses utiles là où la question est déjà posée ;
- une fiche dans les annuaires et boutiques d'intégrations du créneau.

## Règles d'arrêt

- Aucune précommande après 8 semaines : abandonner l'idée, garder le code réutilisable, en tester une autre.
- Trois essais au plus la première année. Au-delà, la méthode ne convient pas.
- Aucune fonction nouvelle tant que cinq clients n'ont pas demandé la même.
- Le domaine n'est acheté qu'une fois la phrase d'offre écrite.
